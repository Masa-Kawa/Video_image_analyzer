# 評価器リファレンス

腹腔鏡下胆嚢摘出術の動画を解析する5つの評価器と、1つのシーン境界検出器の技術資料。

各評価器は2ステップのパイプライン（動画→CSV→JSONL+SRT）で動作し、同じ出力形式を共有する。

---

## 1. 腹腔内外判定 (`cavity_detector`)

**ソース**: `src/cavity/cavity_detector.py`
**サンプリング**: 2fps
**GPU**: 不要

### 目的

カメラが腹腔の中にあるか外にあるかを判定する。手術の有効区間（体内にカメラがある時間）を特定するための前処理として使う。

### 4つの判定指標

#### 1-1. vignette_score（周辺暗域スコア, 重み 0.35）

腹腔鏡のスコープは丸い筒を通して映像を撮る。そのため体内の映像は中央が明るく、周辺が暗い円形の影（ビネット）を持つ。体外の映像にはこの影がない。

**計算方法**:
1. フレームをグレースケールに変換
2. 画像中心からの距離でリング状の外周領域と中央領域を定義
3. 外周リングの平均明度と中央の平均明度の比を計算
4. 明度の比率と外周の絶対的な暗さを 6:4 で合成

```
darkness_ratio = max(0, 1 - ring_mean / center_mean)
absolute_darkness = max(0, 1 - ring_mean / 80)
vignette_score = 0.6 * darkness_ratio + 0.4 * absolute_darkness
```

**値の意味**: 0 = 周辺暗域なし（体外）, 1 = 強い暗域（体内）

#### 1-2. tissue_ratio（組織色占有率, 重み 0.30）

腹腔内は臓器、脂肪、結合組織で画面が覆われ、赤/茶/黄の色相が支配的になる。腹腔外は手術用ドレープ（青/緑）、金属器械（銀）、皮膚など多様な色が混在する。

**計算方法**:
1. フレームをHSV色空間に変換
2. 組織色を定義: 色相(H) 0-35 または 165-179、かつ彩度(S) > 30、明度(V) > 30
3. ROI内の組織色画素数 / 全画素数 を算出

**値の意味**: 0 = 組織色なし（体外）, 1 = 全面が組織色（体内）

#### 1-3. brightness_bimodality（明るさ二峰性, 重み 0.15）

腹腔内はライトが当たる中心が明るく周辺が暗いため、明度ヒストグラムが2つの山を持つ。体外は照明が均一で1つの山になりやすい。

**計算方法**:
1. 暗い画素（V < 50）の比率 dark_ratio と明るい画素（V > 100）の比率 bright_ratio を計算
2. 両方が5%未満なら 0 を返す
3. 二峰性 = min(dark, bright) / max(dark, bright)
4. dark_ratio が 15-70% の範囲にあれば腹腔内の典型パターンとしてペナルティなし

**値の意味**: 0 = 単峰分布（体外）, 1 = 二峰分布（体内）

#### 1-4. hue_concentration（色相集中度, 重み 0.20）

腹腔内は赤-黄の狭い色相帯に画素が集中する。体外は青・緑・銀など広い色相帯に画素が分散する。

**計算方法**:
1. 彩度(S) > 30 かつ明度(V) > 30 の画素の色相を収集（低彩度・低明度の画素は色相が不安定なため除外）
2. 色相を36ビンのヒストグラムにする
3. ヒストグラムの情報エントロピーを計算
4. 最大エントロピー（完全一様分布, log2(36)）に対する比率で集中度を定義

```
entropy = -sum(p * log2(p))
concentration = 1 - entropy / log2(36)
```

**値の意味**: 0 = 色が分散（体外）, 1 = 色が集中（体内）

#### 統合スコア

```
cavity_score = 0.35 * vignette + 0.30 * tissue + 0.15 * bimodality + 0.20 * hue_concentration
```

平滑化後の smooth_cavity が閾値（デフォルト 0.35）以上の連続区間を「INSIDE」、それ以外を「OUTSIDE」として出力する。最小区間長 3.0秒未満の区間は除去する。

### CSVカラム

| カラム | 内容 |
|---|---|
| `vignette_score` | 周辺暗域スコア |
| `tissue_ratio` | 組織色占有率 |
| `brightness_bimodality` | 明るさ二峰性 |
| `hue_concentration` | 色相集中度 |
| `cavity_score` | 統合スコア（上記4指標の重み付き平均） |
| `smooth_cavity` | cavity_score の移動平均 |

### 出力SRT例

```
1
00:00:00,000 --> 00:00:31,500
[cavity] OUTSIDE

2
00:00:31,500 --> 00:34:00,000
[cavity] INSIDE
```

## 2. 赤色率ベース出血検出 (`redlog`)

**ソース**: `src/red/redlog.py`
**サンプリング**: 5fps
**GPU**: 不要

### 目的

画面全体の赤色率の時間変化を記録し、赤色が急増する区間を出血候補として検出する。最もシンプルな出血検出手法。

### 仕組み

#### 赤色率の計算

各フレームをHSV色空間に変換し、赤色画素の割合を求める。

```
赤色条件: (H in [0, 10] or H in [170, 179]) and S >= 60 and V >= 40
red_ratio = 赤色画素数 / ROI内全画素数
```

HSV色空間では赤は色相(H) 0度付近に位置するが、0度と180度の境界をまたぐため、0-10 と 170-179 の2つの範囲を使う。彩度(S)と明度(V)の下限は、暗すぎる画素や灰色の画素を赤と誤判定しないためのフィルタ。

#### delta（変化率）

```
delta[i] = red_ratio[i] - red_ratio[i-1]
```

前フレームとの差分。正の delta は赤色の増加、負の delta は赤色の減少を意味する。

#### smooth_delta（平滑化変化率）

delta を中心移動平均で平滑化する。窓サイズはデフォルトで 5秒 * 5fps = 25フレーム。

#### イベント検出

smooth_delta が閾値（デフォルト 0.03）を連続 3秒以上超えたら出血候補イベントとする。

### 弱点

カメラが動くと画面全体の赤色率が変わるため、赤い臓器がフレームに入ってきただけでも反応する。カメラ移動と実際の出血を区別できない。この弱点を補うために bleed_detector と bleed_spread が作られた。

### CSVカラム

| カラム | 内容 |
|---|---|
| `red_ratio` | 赤色画素の占有率（0-1） |
| `delta` | 前フレームとの赤色率差分 |
| `smooth_delta` | delta の移動平均 |

## 3. 赤色拡大検出 (`bleed_detector`)

**ソース**: `src/red/bleed_detector.py`
**サンプリング**: 5fps
**GPU**: 不要

### 目的

「背景が動いていないのに赤色だけが増えた」現象を出血として検出する。redlog の弱点であるカメラ移動による誤検出を抑制する。

### 仕組み

連続する2フレーム（N-1 と N）を比較して3つの中間指標を計算し、最終スコアを導出する。

#### 3-1. newly_red_ratio（新規赤化率）

```
newly_red = (N で赤) AND (N-1 で赤でない) の画素
newly_red_ratio = newly_red の画素数 / ROI内全画素数
```

「新しく赤くなった面積」を測る。前フレームですでに赤かった画素は含まない。出血は時間とともに赤い領域が広がる現象なので、新規に赤化した領域の割合が出血の直接的な指標になる。

#### 3-2. bg_stability（背景安定度）

```
gray_diff = |gray(N) - gray(N-1)|     # グレースケールのフレーム間差分
bg_diff = 非赤領域の gray_diff の平均値
bg_stability = 1 - min(bg_diff / 30, 1)
```

赤以外の領域がどれだけ動いていないかを測る。カメラが動くと非赤領域のフレーム差分も大きくなるため、bg_stability が下がる。30 は正規化係数で、平均差分が 30 以上で安定度 0 になる。

#### 3-3. red_expansion（赤色拡大指標）

```
red_expansion = newly_red_ratio * bg_stability
```

背景が安定しているときだけ赤の拡大を評価する。カメラが動いている場合（bg_stability が低い）は newly_red_ratio が大きくても red_expansion は小さくなり、誤検出を抑える。

#### イベント検出

smooth_expansion（red_expansion の移動平均）が閾値（デフォルト 0.005）を連続 1秒以上超えたら出血候補イベントとする。

### redlog との違い

| 比較項目 | redlog | bleed_detector |
|---|---|---|
| 指標 | 赤色率の変化（全体） | 新規赤化 * 背景安定度 |
| カメラ移動 | 誤検出する | 背景の動きで減衰される |
| 閾値 | delta > 0.03 | expansion > 0.005 |
| 感度 | 高い（偽陽性多め） | 中程度（偽陽性抑制） |

### CSVカラム

| カラム | 内容 |
|---|---|
| `red_ratio` | 赤色率 |
| `newly_red_ratio` | 新規赤化率 |
| `bg_stability` | 背景安定度（0=動いている, 1=静止） |
| `red_expansion` | 赤色拡大指標 = newly_red * bg_stability |
| `smooth_expansion` | red_expansion の移動平均 |

## 4. 局所赤色拡散検出 (`bleed_spread`)

**ソース**: `src/red/bleed_spread.py`
**サンプリング**: 5fps
**GPU**: 不要

### 目的

「画面の一部だけで赤色が増え、他は変わらない」パターンを出血として検出する。bleed_detector がカメラの静止を前提とするのに対し、bleed_spread はカメラがゆっくり動いていても局所的な赤の拡散を検出できる。

### 仕組み

#### グリッド分割

フレームを 8x8 = 64 セルに分割する。各セルの赤色率を独立に計算する。

```
cell_ratios[r][c] = セル(r,c) 内の赤色画素数 / セル(r,c) 内のROI画素数
```

#### セル差分

```
cell_deltas[r][c] = cell_ratios[r][c](N) - cell_ratios[r][c](N-1)
```

各セルの赤色率の前フレームとの差分。

#### 拡散スコアの導出

cell_deltas 全64セルの統計量から2つの値を計算する:

**delta_std**（標準偏差）: セル間の差分のばらつき。
- 小さい = 全セルが均等に変化 = カメラ移動
- 大きい = 一部セルだけ変化 = 局所イベント

**max_cell_delta**: 正の方向に最も大きく変化したセルの差分値。

```
spread_score = delta_std * max_cell_delta
```

標準偏差が大きく（局所的な変化）、かつ最大差分も大きい（明確な変化）場合にだけ高いスコアになる。

#### なぜカメラ移動に耐性があるか

カメラが水平移動すると、画面全体の赤色率が変わるが、その変化は全セルでほぼ均等に起こる。64セル全部が +0.02 ずつ変化すれば delta_std はほぼ 0 になる。一方、出血は画面の一箇所で起こるため、1-3個のセルだけが大きく変化し、残りは変化しない。この不均一さが delta_std を大きくする。

### bleed_detector との違い

| 比較項目 | bleed_detector | bleed_spread |
|---|---|---|
| カメラ移動対策 | 背景の動き量で減衰 | セル間のばらつきで判定 |
| ゆっくりカメラ移動 | 背景がわずかに動くと反応低下 | 均等移動は除去される |
| 大きな出血 | 画面全体が赤くなると反応 | 画面全体が均等に変化すると反応しにくい |
| 適した場面 | カメラが止まっている場面 | カメラが動いていても検出したい場面 |

### CSVカラム

| カラム | 内容 |
|---|---|
| `red_ratio` | 赤色率（全体） |
| `max_cell_delta` | 最も変化したセルの差分値 |
| `delta_std` | 64セルの差分の標準偏差 |
| `spread_score` | 拡散スコア = delta_std * max_cell_delta |
| `smooth_spread` | spread_score の移動平均 |
| `n_rising_cells` | 赤色率が 0.01 以上増加したセル数 |

## 5. 手術フェーズセグメンテーション (`phase_segmenter`)

**ソース**: `src/phase/phase_segmenter.py`
**サンプリング**: 1fps
**GPU**: 推奨（ResNet-18 使用時）

### 目的

手術動画を時間的なフェーズ（工程）に分割する。教師データ（正解ラベル）なしで動作する教師なし手法。

### 7つのターゲットフェーズ

| ID | フェーズ名 | 内容 |
|---|---|---|
| 0 | Preparation | 手術準備、ドレーピング |
| 1 | Port insertion | トロカール挿入、気腹 |
| 2 | Observation | 腹腔内の観察 |
| 3 | Neck handling | 胆嚢頸部の把持・牽引 |
| 4 | Dissection | Calot三角の剥離、クリッピング |
| 5 | Irrigation | 洗浄・吸引・ドレーン |
| 6 | Extraction | 胆嚢摘出、閉創 |

### 処理の流れ（5段階）

#### 5-1. 特徴量抽出

各フレームをResNet-18（ImageNetで学習済みの画像認識モデル）に入力し、最終全結合層の手前で512次元のベクトルを取り出す。

```
BGRフレーム → RGB変換 → リサイズ(256) → 中央クロップ(224) → 正規化 → ResNet-18 → 512次元ベクトル → L2正規化
```

このベクトルは「その映像が何に見えるか」を圧縮した表現。似た見た目のフレーム同士はベクトルも近くなる。

**GPUが使えない場合のフォールバック**: HSVヒストグラム（18+8+8=34ビン）と統計量（14値）を連結した48次元のヒューリスティック特徴を使う。明度平均、明度標準偏差、色相統計、赤色率、暗領域率、エッジ密度、テクスチャ量、コントラストなどを含む。

#### 5-2. コサイン類似度

隣接フレームの特徴ベクトルのコサイン類似度を計算する。

```
similarity[i] = dot(feature[i-1], feature[i])
```

L2正規化済みのベクトル同士の内積はコサイン類似度に等しい。値が 1 に近いほど前後のフレームが似ている。値が下がると映像の見た目が変わったことを意味する。

#### 5-3. 変化点検出

平滑化した類似度の時系列から、急激に下がった点をフェーズの切り替わり（変化点）として検出する。

```
各時点 i について:
  local_mean = 前後 window フレームの類似度の平均
  local_std  = 前後 window フレームの類似度の標準偏差

  if similarity[i] < local_mean - sensitivity * local_std:
      → 変化点
```

sensitivity（デフォルト 1.5）が大きいほど検出が控えめになり、フェーズ数が減る。min_phase_s（デフォルト 30秒）未満の間隔で検出された変化点は、より強い方（類似度が低い方）だけを残してマージする。

#### 5-4. K-means クラスタリング

変化点でセグメントに分割した後、各セグメントの平均特徴ベクトルを K-means でクラスタリングする。

**初期化**: 時間的に均等な位置のセグメントをセントロイドに選ぶ。
**距離**: ユークリッド距離。
**反復**: 最大50回、収束したら終了。

似た見た目のセグメント同士が同じクラスタにまとまる（例: 同じ工程を映した別の区間）。

#### 5-5. フェーズ名マッピング（ヒューリスティック）

各セグメントの時間的位置と視覚特徴からフェーズ名を割り当てる。正解ラベルがないため、手術の一般的な時間構成に基づくルールで推定する。

```
temporal_pos = セグメント中央の時刻 / 総時間    （0 = 動画冒頭, 1 = 動画末尾）
seg_brightness = セグメント内の平均明度
seg_tissue = セグメント内の平均組織色率
```

| 時間位置 | 条件 | フェーズ |
|---|---|---|
| 0-10% | 明るい (> 100) | Preparation |
| 0-10% | 暗い | Port insertion |
| 10-20% | 組織色少ない (< 0.15) | Port insertion |
| 10-20% | 組織色あり | Observation |
| 90-100% | - | Extraction |
| 80-90% | 組織色少ない (< 0.20) | Irrigation |
| 80-90% | 組織色あり | Extraction |
| 20-80% | 組織色多い (> 0.40) | Dissection |
| 20-80% | 組織色中程度 (> 0.25) | Neck handling |
| 20-80% | 組織色少ない | Observation |

### CSVカラム

| カラム | 内容 |
|---|---|
| `brightness` | 平均明度（0-255） |
| `tissue_ratio` | 組織色占有率（0-1） |
| `similarity` | 前フレームとのコサイン類似度 |
| `smooth_similarity` | similarity の移動平均 |

### 追加出力

`{stem}_features.npy`: 全フレームの特徴ベクトル行列（N x 512）。annotate ステップで使用するため、このファイルが必要。特徴抽出をやり直さずにパラメータだけ変えて再アノテーションできる。

### 出力SRT例

```
1
00:00:00,000 --> 00:00:32,000
[phase] Preparation

2
00:00:32,000 --> 00:01:45,000
[phase] Port insertion

3
00:01:45,000 --> 00:05:10,000
[phase] Observation
```

## 6. シーン境界検出 (`transnet_to_srt`)

**ソース**: `src/transnet/transnet_to_srt.py`
**入力**: TransNetV2 が出力した境界時刻 JSONL
**GPU**: 不要（TransNetV2 の推論自体は別途行う）

### 目的

TransNetV2（ショット境界検出の深層学習モデル）が出力した境界時刻を、他の評価器と同じ SRT + JSONL 形式に変換する。カットの検出自体はTransNetV2が行い、このモジュールは変換のみを担当する。

### 入力形式

```jsonl
{"t_sec": 615.2, "score": 0.93}
{"t_sec": 720.5, "score": 0.87}
```

`t_sec`: 境界が検出された時刻（秒）。`score`: 検出確信度（0-1, 任意フィールド）。

### 変換方法

境界の瞬間は点（duration = 0）なので、前後に pad_ms（デフォルト 100ms）のパディングを加えて短い区間にする。

```
開始 = max(0, t_sec - pad_ms/1000)
終了 = t_sec + pad_ms/1000
```

### 出力SRT例

```
1
00:10:15,100 --> 00:10:15,300
[cut] transnet

2
00:12:00,400 --> 00:12:00,600
[cut] transnet
```

## 出血検出3手法の使い分け

| 状況 | 推奨手法 | 理由 |
|---|---|---|
| まず全体像を把握したい | redlog | 最もシンプル。偽陽性は多いが見落としが少ない |
| カメラが固定されている場面 | bleed_detector | 背景安定度による判定が最も有効に機能する |
| カメラがゆっくり動いている場面 | bleed_spread | セル間ばらつきでカメラ移動を除去できる |
| 最終的な出血候補リスト | 3手法のAND/OR | 複数手法で一致した候補は信頼度が高い |

## 共通の前処理

### 円形ROI

腹腔鏡映像は円形の視野を持ち、四隅は常に黒い。この四隅を計測に含めると指標が歪む。円形ROIマスク（`make_circular_roi()`）は画像中心から半径 `min(H,W) * (0.5 - margin)` の円内だけを計測対象とする。margin のデフォルトは 0.08（周辺8%を除外）。

### 赤色の定義

全ての出血検出器はHSV色空間で赤色を定義する:
- **色相(H)**: 0-10 または 170-179（HSVの赤は 0度/180度 の境界にまたがる）
- **彩度(S)**: 60 以上（灰色を除外）
- **明度(V)**: 40 以上（暗すぎる画素を除外）

### 移動平均

`smooth_center()` は中心移動平均を計算する。窓サイズ = smooth_s * fps フレーム。端ではウィンドウを縮小して対応する。ノイズの多い生の指標を平滑化してから閾値判定することで、瞬間的なスパイクによる誤検出を防ぐ。

### イベント検出の共通ロジック

`extract_bleed_events()` は「平滑化した指標が閾値を k_s 秒以上連続して超えた区間」をイベントとして抽出する。このロジックは redlog, bleed_detector, bleed_spread の3つで共有される。
